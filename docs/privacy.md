# Privacy and data ownership

Aligner Tracker is a free GPL-3.0-or-later application. It has no required account/backend, advertising, billing, analytics or diagnostic image analysis. The phone owns treatment, wear events, schedule revisions, actual tray changes, historical targets, notes, appointments and dated photos. Records remain usable offline. No feature automatically advances treatment or sends a report.

Room and normalized JPEG copies live in app-private storage protected by Android's sandbox/device encryption. This is not separate application-level database encryption. Automatic Android backup/device-transfer inclusion is disabled by manifest and exclusion rules. Keep a portable backup before uninstalling or changing devices.

The system Photo Picker grants access to selected images only. The app copies, bounds/resizes, rotates and re-encodes those images locally; source metadata, including location, is not retained. The original chosen image remains owned by its source provider. Photo comparison and exported HTML time-lapse make no diagnostic claims. The self-contained time-lapse contains embedded private images and makes no network requests.

Complete ZIP backups contain versioned records and their photo copies. Encrypted ATBK backups protect that archive using authenticated encryption and a password KDF; see [format](encrypted-backup.md). Plaintext ZIP/legacy JSON, CSV reports and HTML photo exports are readable by anyone with the exported file. A system document provider can upload an export if the user chooses a cloud destination. The app never chooses a destination or sends files automatically. Lost encryption passwords cannot be recovered; wrong-password/corruption errors leave existing records untouched.

Restore validates the entire bounded archive, references, timestamps and photo hashes/dimensions before explicit replacement. Photo blobs are staged under newly generated private names before the Room replacement transaction; failure cleans staging and retains prior records. Schema1 imports remain supported. Device-local notification grants, channel settings, reminder preferences, optional streak preference, clock observations, watch pairing state and command receipts are not portable treatment records. Restore preserves this device's reminder choices, cancels stale delivery state and rotates the synchronization generation. Delete data resets reminder/streak preferences, removes treatment data/private photo copies, invalidates remote commands and cancels pending reminders. Exported files and originals must be deleted separately.

The optional Wear OS companion bundles the Apache-2.0 microG Wear client rather than Google’s proprietary client libraries. This is a client-library replacement; it does not install or replace Google Play services on a device. Phone treatment features remain usable without Google Play services. Watch communication requires a compatible installed Wear Data Layer service and paired-device stack; current transport evidence uses official Google Play services.

Only compact current status and explicit commands/outcomes are exchanged; photos, notes, appointments and full history are not sent. The watch keeps its acknowledged state and durable pending actions locally. It attempts delivery only to a nearby node and shows rejected stale commands for user review. The phone applies accepted watch actions at phone receipt time; offline watch time is never silently inserted into phone history. No custom backend or optional cloud synchronization is implemented. Neither APK requests INTERNET. On the tested Google runtime, Google controls the Data Layer transport: its [documentation](https://developer.android.com/training/wearables/data/overview) describes Bluetooth and cloud routing. Requiring a nearby node constrains app delivery attempts; it is not proof that Google services never use external infrastructure. Replacing the bundled client does not change that privacy boundary. Physical transport/reconnection validation remains a release gate; see [Wear notes](wear.md).

Notifications are optional and private on the lock screen, with generic public content. Android permissions, channels, exact-alarm access, Doze, force-stop and OEM policies control delivery. No continuously ticking background service or battery-exemption request is used. No guarantee is made that reminders bypass Android restrictions.

This describes implementation intent and lifecycle; current evidence and remaining gates are in [validation](validation.md) and the [finite v1 checklist](v1-checklist.md). It is not legal certification or a release-readiness claim.

Temporary camera captures are tracked privately while the external camera is open. Cancellation/import deletes the temporary original. To allow a camera result to survive process recreation, a still-active capture has a 24-hour recovery grace period; the next app start after that period removes it. Delete data removes all temporary captures immediately. This grace does not apply to normalized saved photos, which remain until explicitly deleted.

Portable archives are bounded to 32 MiB, with a clear size error before replacement; keep the previous good backup if a larger collection needs reducing. Offline photo time-lapse output is bounded to 16 MiB and 100 frames; select fewer images if the size limit is reached.

The phone remembers dismissal of the optional treatment-setup invitation in local
presentation preferences. This UI choice is tied to the tracking session, is not
included in portable treatment backups, and never changes treatment records.
